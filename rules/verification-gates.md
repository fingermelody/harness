# 质量门禁系统

> 多层质量门禁规则，确保每个阶段的交付物都达到预期标准。

## 门禁层级总览

```
┌──────────────────┐
│  TEST-PLAN Gate  │  ← PLAN→CODE 前：测试用例骨架评审
│  ~10 分钟        │
└────────┬─────────┘
         ↓
┌──────────────────┐
│  REVIEW Gate     │  ← CODE→DEPLOY-TEST 前：代码 Review
│  ~5 分钟         │
└────────┬─────────┘
         ↓
┌──────────────────┐
│  DEPLOY-TEST     │  ← REVIEW→TEST-RUN 前：部署 + Health Check
│  ~5 分钟         │
└────────┬─────────┘
         ↓
┌──────────────────┐
│  TEST-RUN Gate   │  ← DEPLOY-TEST 后：全量 E2E + 回归
│  ~15 分钟        │
└────────┬─────────┘
         ↓
┌──────────────────┐
│  EVAL Gate       │  ← TEST-RUN→DEPLOY-PROD 前：综合评分
│  ~5 分钟         │
└────────┬─────────┘
         ↓
┌──────────────────┐
│  DEPLOY-PROD     │  ← 上线前：灰度 + 回滚策略 + PM 审批
│  ~10 分钟        │
└──────────────────┘
```

## 门禁详解

### TEST-PLAN Gate（PLAN → CODE）

**前置条件**：
- [ ] 核心功能的测试用例骨架已输出（BDD Scenario 覆盖主要路径）
- [ ] 测试用例经过 Planner + Coder 联合评审
- [ ] 测试数据准备方案已确认

### REVIEW Gate（CODE → DEPLOY-TEST）

**前置条件**：
- [ ] **Reviewer Agent 评审完成**（必选）
- [ ] 代码变更范围合理（单次 ≤ 500 行新增/修改）
- [ ] 无明显的架构问题或性能风险

**Review 检查维度**：
- **正确性**：逻辑无误、边界处理完整、空值安全
- **可读性**：命名清晰、注释到位、函数长度 ≤ 30 行
- **可测性**：是否支持测试（无硬编码、可 mock）
- **性能**：无 N+1 查询、无同步大文件
- **安全**：无注入风险、敏感信息未硬编码

### DEPLOY-TEST Gate（REVIEW → TEST-RUN）

**前置条件**：
- [ ] 测试环境部署成功
- [ ] Health Check 所有关键路由返回 200
- [ ] 数据库迁移已完成（如有）

### TEST-RUN Gate（DEPLOY-TEST → EVAL）

**前置条件**：
- [ ] E2E 主流程 100% 通过
- [ ] 单元/集成测试全部通过
- [ ] 无 P0 Bug，P1 Bug ≤ 2 个且有 workaround
- [ ] 性能测试符合基线（LCP < 2.5s）

### EVAL Gate（TEST-RUN → DEPLOY-PROD）

**前置条件**：
- [ ] 综合评分 ≥ 80（PASS）
- [ ] 所有质量维度无 BLOCK 项
- [ ] CHANGELOG 已更新

---

## 评分等级

| 等级 | 分数 | 含义 | 操作 |
|------|------|------|------|
| **A+** 🏆 | 90-100 | 卓越 | 可以作为标杆案例 |
| **A** ✅ | 80-89 | 优秀 | 通过门禁，允许部署 |
| **B** ⚠️ | 70-79 | 良好 | 需关注，PM 确认后可部署 |
| **C** 🔶 | 60-69 | 及格边缘 | 需要列出改进计划 |
| **F** 🚫 | 0-59 | 不合格 | 阻止部署，打回修复 |
